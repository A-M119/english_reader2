# データファイルの形式

このアプリは、原文・和訳・単語の意味・文構造をまとめた**1つのJSONファイル**を読み込みます。
アプリ自体は翻訳や解析を行いません。JSONファイルは、Claudeなどとのチャットで事前に作成してください。

## スキーマ

```json
{
  "title": "作品名",
  "sentences": [
    {
      "id": 0,
      "en": "原文の1文",
      "ja": "和訳（任意）",
      "words": [
        { "word": "単語・熟語", "meaning": "意味の説明" }
      ],
      "glossary": [
        { "word": "原文中の単語", "meaning": "意味" }
      ],
      "structure": "文構造の説明（任意）",
      "parse": {
        "clauses": [
          { "id": 1, "label": "節の説明" }
        ],
        "tokens": [
          { "w": "Alice", "pos": "名", "role": "S", "c": 1 },
          { "w": "was", "pos": "助", "role": "V", "c": 1 },
          { "w": "and", "pos": "接" }
        ]
      }
    }
  ]
}
```

- `sentences` は必須。1文につき1オブジェクト。
- `en` のみ必須。`ja` / `words` / `glossary` / `structure` / `parse` は無くても動作します（アプリ側で「データなし」と表示されます）。
- `words` は「翻訳」パネルに出る熟語・表現のメモ、`glossary` は「単語」ボタンで和訳なしに確認できる単語ごとの意味です。
  - `words` の数に上限はありません。熟語・構文・決まり文句は漏れなく挙げます。
  - `glossary` の対象は「TOEIC 450点（英検3級〜準2級、CEFR A2）程度を超える単語」、つまり中学の基本語より難しい単語すべてと、「基本語でも文脈で特殊な意味になるもの」（bank＝土手、curious＝奇妙な など）。
  - `word` は原文に出てくる形のまま書きます（原文中の該当箇所に下線が付きます）。活用形の場合は `meaning` に原形を添えます。
  - 該当する単語が無い文は空配列 `[]`。`glossary` 自体が無い場合は `words` で代用されます。
- `id` は省略可（省略時は配列のインデックスが使われます）。

### `parse`（「構造」ボタン）

原文の各語の品詞と、文の成分（主語・述語動詞など）を表します。

- `tokens`：原文の語を**出てくる順番どおり**にすべて並べます。句読点や引用符は含めません。
  - `w`：原文に出てくる形のまま。短縮形は `they` + `'ll`、`I` + `'ve` のように分けられます（`didn't` などの否定の短縮形は1語のまま「助」）。
  - `pos`：品詞の略号。名=名詞 代=代名詞 動=動詞 助=助動詞 形=形容詞 副=副詞 冠=冠詞 前=前置詞 接=接続詞 間=間投詞
  - `role`：文の成分。S=主語（主部） V=述語動詞 O=目的語 C=補語 M=修飾語。どれにも当たらない語（節をつなぐ接続詞、間投詞、呼びかけ）は省略します。
  - `c`：その語が属する節の番号（`clauses` の `id`）。
- `clauses`：節ごとの説明。主節・従属節・関係詞節・挿入節などの種類と、主語・動詞・補語の関係を短く書きます。
- 分け方のルール：
  - 助動詞 + 動詞、begin to / try to / manage to などの「動詞 + to 不定詞」で1つの動作を表すもの、not / never が間に入ったものは、まとめて1つの V にします（`was beginning to get`、`did not like to drop`）。
  - 不定詞の to は「前」とします。
  - 名詞の前の my / her / their は「代」、no / some / every / this（名詞の前）は「形」とします。
  - 進行形・受け身の be、完了形の have、疑問文・否定文の do は「助」とします。
  - 関係詞節・that 節・疑問詞節などの従属節は別の節番号にし、その節の中での成分を付けます。節が文全体の中でどんな役割か（~の目的語、~を修飾など）は `clauses` の説明に書きます。
- 検証：`node scripts/check-book.js books/<slug>.json` で、語の並び順・品詞の付け漏れ・略号の誤りをチェックできます。

## 作成方法（Claudeへの依頼例）

小説のtxtファイルの内容をコピーしてClaude（claude.aiなど）に貼り付け、以下のようなプロンプトで依頼してください。

```
以下は英語小説の抜粋です。この文章を1文ずつに分割し、各文について
「和訳」「文中の重要単語とその意味」「文構造の簡単な説明」を付けて、
下記のJSON形式で出力してください。

{
  "title": "作品名",
  "sentences": [
    {
      "id": 0,
      "en": "原文の1文",
      "ja": "和訳",
      "words": [{ "word": "単語", "meaning": "意味" }],
      "structure": "文構造の説明"
    }
  ]
}

出力はJSONのみにしてください。

---
(ここに小説のtxt本文を貼り付ける)
---
```

出力されたJSONをテキストファイルとして保存し（拡張子は `.json`）、アプリの「JSONファイルを選択」から読み込んでください。

## 長編小説を扱う場合の注意

一度に大量の文をLLMに渡すと、出力が省略されたり精度が落ちたりすることがあります。
章単位・数百文単位など、無理のない分量に分けて依頼し、生成したJSONを結合して使うことをおすすめします
（`sentences` 配列を単純につなげれば1つのファイルにまとめられます）。

## Claude Codeでの変換（`/convert-book` スキル）

このリポジトリをClaude Codeで開いている場合は、上記の手作業の代わりに
`.claude/skills/convert-book/` に用意したスキルを使えます。txtファイルを渡して
「このtxtを変換して」と頼むと、Gutenbergのライセンス文除去・文字化け修正・章分割
（`scripts/clean-source.js`）から、章ごとの文単位の翻訳・単語解説・文構造解析まで、
このドキュメントのスキーマに沿って進めます（`parse` を含む）。実例として
`books/alice-in-wonderland.json`（Chapter Iの45文）を参照してください。
